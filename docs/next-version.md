# 0.7 设计方案：配置方案与外观工作区

状态：设计待确认，中心交互规则已确认。当前已实现能力及测试状态分别见 [产品设计](product-design.md) 与 [验证记录](validation.md)。本文件是下一版需求的唯一来源。

## 目标与范围

保留中键单手操作、两级轮盘、便携存储与即时保存，增加可复用的应用工作流及高级外观编辑。高级选项放在独立折叠面板，默认使用预设。以下模块均纳入本次候选范围，不将既有能力重复立项。

| 模块 | 交付范围 |
| --- | --- |
| 共享图标库 | 本地 SVG／PNG／ICO／JPG 导入；搜索、选择、重命名、删除；主轮盘、子轮盘和中心动作共用。 |
| 配置方案 | 全局方案与应用专属方案；新建、复制、重命名、删除及应用绑定。 |
| 动作工作区 | 左侧方案及聚焦编辑卡片，右侧实时画布；保留紧凑动作全览及两级导航。 |
| 预览画布 | 滚轮缩放、中键拖动平移、复位、点击选中、拖拽换位；参数即时可见。 |
| 主题与材质 | 跟随系统、浅色、深色、护眼、莫兰迪柔灰及少量配色；毛玻璃材质与配色分离。 |
| 颜色编辑 | 扇区底色、高亮光晕、边框与文字颜色；十六进制输入、色盘、屏幕吸色。 |
| 颜色预设 | 保存当前颜色，支持重命名、删除；删除色板不改变已应用的颜色。 |
| 槽位排版 | 按槽位覆盖图文布局、字体、字号、文字颜色、图标尺寸、文字位置及 X／Y 偏移；可恢复继承。 |
| 中心动作 | 仅主轮盘中心可启用独立动作，默认关闭；支持死区松开执行、常用动作预设及独立图文排版。 |
| 屏幕适配 | ScreenHelper 统一多屏、混合 DPI、坐标转换、防溢出策略及 X／Y 安全边距。 |
| 环境放行 | 复用并完善排除名单与全屏放行；匹配到专属方案也不得绕过放行规则。 |
| 多语言 | 简体中文、繁体中文、English、日本語；切换即时生效，保留草稿、当前方案和画布视角。 |

## 图标库

- 导入文件复制到配置目录内的图标资源目录，配置仅保存相对资源标识；移动整个便携目录后仍可使用。
- SVG 保留矢量原文件，按显示尺寸渲染；不能沿用现有全部缩小为 PNG 的导入链路作为矢量存储。位图使用独立缩略图缓存，ICO 选择合适分辨率。
- 原始来源文件不被修改。相同内容去重，显示名称独立于文件名与资源标识，重命名不影响已配置槽位。
- 删除图标时显示引用数量；被引用图标需明确选择替换为自动图标或取消。配置提交失败时不得先删除资源。
- 旧配置中的自定义图片迁入资源库；程序图标与网站自动图标继续保留原有自动获取语义。

## 方案选择与继承

- 方案使用稳定标识；复制生成新标识。全局方案始终存在，支持编辑但不删除。
- 应用按规范化完整可执行文件路径绑定，不按窗口标题或显示名称匹配；一个方案可绑定多个程序，同一路径只绑定一个专属方案。
- 决策顺序：暂停／排除／全屏放行 → 前台程序专属方案 → 全局方案。
- 在按下触发键时记录方案、前台窗口及配置快照；一次操作中不切换方案。前台窗口改变时按既有规则取消当前轮盘。
- 全局设置保存触发、语言与放行规则；方案拥有轮盘内容、主题选择与布局参数。图标库和颜色预设跨方案共用。
- 复用 [应用发现](../src/platform/application_catalog.h)、[应用选择器](../src/ui/application_picker.h) 与 [窗口上下文](../src/platform/window_context.h)，统一服务启动目标、绑定方案和排除名单。
- 运行窗口入口列出窗口及其所属进程，并可直接选择；保留名称搜索、来源过滤和手动浏览 EXE。

## 主题与编辑画布

- 颜色继承顺序为内置主题 → 当前方案覆盖 → 当前槽位覆盖。未覆盖字段继续随主题变化，恢复继承不能复制一份默认值。
- “跟随系统”监听系统配色变化，不通过空闲轮询实现。颜色与毛玻璃材质分开表示；真实背景模糊的可用性需分别验证 Windows 10／11，不把普通半透明标为真实模糊。
- 色板预设保存颜色值，选用后写入当前覆盖字段；色板重命名、删除不反向修改已有外观。
- 图文布局模式指仅图标、文字上下／左右等内容排版；四种轮盘形态继续决定槽位外形与命中区域。
- 画布缩放和平移只影响编辑视图，不修改真实轮盘尺寸。绘制与命中共用同一坐标变换；屏幕吸色退出后恢复编辑与输入状态。
- 拖拽交换包含动作、图标、名称和排版。主／子层之间通过分组导航完成拖放；普通动作可与主中心互换，分组不可放入子层或中心，避免产生第三级轮盘。

## 中心与屏幕边缘

已确认：仅主轮盘中心可配置执行动作，子轮盘中心始终返回上一级。

- 中心执行默认关闭；关闭时保持原有取消行为。启用后，中键在中心死区内松开执行中心动作；轮盘外释放及 Esc 继续取消。
- 死区半径／灵敏度与可见中心提示一致；外层槽位不与中心命中区域重叠。展开子轮盘后的防误执行规则继续保留。
- 边缘策略提供优先平移与优先缩放；以目标显示器工作区为边界，X／Y 安全边距使用逻辑像素。
- 防溢出计算包含图标、文字偏移、边框与光晕的完整可见范围。空间不足时按统一策略调整，不能只约束基础圆形包围盒。
- ScreenHelper 为绘制、命中、吸色、触发位置和预览提供共享转换，覆盖副屏负坐标与混合 DPI；不移动用户光标。
- 现有全屏判断是覆盖显示器边界，不是独占渲染模式检测。产品入口采用“全屏应用／游戏放行”，覆盖无边框全屏与游戏场景，并验证原生按键成对放行。

## 实施顺序

1. **统一数据与资源基础**：拆分全局设置、方案、图标资源、颜色预设和可继承样式；保留唯一配置写入口。完成旧配置迁移、资源生命周期、方案匹配及 ScreenHelper 的测试。
2. **工作区与核心交互**：接入图标库、方案管理、右侧画布、跨层拖放、中心动作及安全边距；默认保持旧配置行为。
3. **外观与语言**：接入系统主题、颜色与材质、折叠样式面板、逐槽排版和四语切换；验证吸色、语言切换和未完成草稿的生命周期。

各阶段作为可回滚提交，在同一版本范围内逐步完成；不额外引入第三层轮盘、轨迹手势或宏脚本系统。

## 验收重点

- 删除源文件后图标仍可用；SVG 放大保持矢量渲染；重命名不破坏引用；被引用资源删除与写盘失败无数据丢失。
- Chrome、VS Code 等专属方案与全局回退，重复绑定、复制、删除、前台变化、排除和全屏放行的优先级正确。
- 各形态、槽位数量、层级及中心在画布缩放／平移后仍可准确点击与换位；运行时与预览采用相同布局结果。
- 中心执行与取消／返回互不混淆；普通点击、快速松键、暂停和全屏期间保持输入配对。
- 四种语言切换不重置配置或草稿；长文本不遮挡控件，异步错误和工具窗口使用当前语言。
- 多屏边缘、负坐标、不同 DPI、任务栏工作区、文字偏移及光晕均纳入边界检查；单屏模拟不能代替真实多屏验收。
- 毛玻璃与吸色验证实际效果；空闲时不持续截图、运行动画、扫描应用或轮询前台进程；记录资源与响应延迟。
